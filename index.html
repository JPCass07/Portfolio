  • No. 01Oct 2026 – nowPersonal

    Flytrap honeypot lab

    A self-hosted honeypot and traffic-analysis lab. Decoy services draw attacks, every packet is captured, and the logs get matched to the packets so an analyst can see exactly what happened. Phase 1 runs today; next it gets one data model across sensors and an MCP server so Claude can query it.

    • Docker
    • Python
    • Cowrie
    • tcpdump
    • Wireshark
    Phase 1 running

    Why

    To learn packet analysis and production-grade security by running something that really gets attacked, and to practise the forward deployed part: taking messy output from different tools and turning it into something a person can act on.

    What runs today · phase 1

    • An isolated Docker network with no route out (internal: true), so it is safe to attack anywhere. I checked: no DNS, and Network unreachable for direct IPs.
    • Cowrie for SSH and Telnet, plus an HTTP decoy I wrote using only the Python standard library: a fake router login and bait files like /.env, logging every request as JSON lines.
    • Rotating tcpdump captures on the lab bridge, so every packet opens in Wireshark.
    • An attacker script that replays a typical opportunistic attack: SYN scan, fingerprinting, web probing, credential stuffing, SSH brute force and post-login commands.
    • Hardened containers: non-root users, every Linux capability dropped (capture keeps only NET_RAW and NET_ADMIN), no-new-privileges, a read-only file system and a 16 KB cap on request bodies.
    • SYN probes304
    • Ports open2of 102
    • Tools, one IP3

    Lab 01 · what I found

    • Traced the whole attack in Wireshark: 304 SYN probes, SYN-ACK from the two open ports and RST from every closed one.
    • Read a credential-stuffing login in plaintext over HTTP, and showed why the SSH password can't be read: encryption starts at the key exchange, before authentication.
    • Joined a decoy log line to its packets by source port and timestamp. That join is what the phase 3 collector will do automatically.
    • One IP switched tools three times (zgrab, curl, Hydra), so events have to be grouped by IP and session, not by user agent.
    • Both of my honeypots can be fingerprinted. The decoy answers HTTP/1.0 under a lighttpd banner, and Cowrie claims OpenSSH 9.2 while offering ciphers OpenSSH dropped years ago. Both are on the fix list.

    The first real bug

    The capture container restart-looped with Permission denied. With every capability dropped, even root inside the container has no DAC_OVERRIDE, so it couldn't write to a host-owned folder. I made the folder writable in setup instead of giving the capability back, which keeps capture at the two capabilities it needs.

    From the decision log

    ChoseOverBecause
    Lab network is internal-onlyA normal bridgeA compromised sensor can't reach the internet
    Standard-library decoyFlask or FastAPINo third-party code to patch on an internet-facing service
    Banners come from .envHard-codedThe code is public, so a live deployment mustn't match the defaults

    Next

    Phase 2: my own certificate authority, TLS on the decoy and mutual TLS between services. Phase 3: one data model across every sensor, a triage app with write-back actions, and an MCP server so Claude can answer "what happened in the last hour?".

    The repository goes public with v0.1.0. Real attacker data is never published unredacted.

  • No. 02Aug – Sep 2026Tanium

    Claude skills for enterprise support

    Claude skills connected to Tanium over MCP, giving support engineers a structured, consistent first response to a new case. Presented at EMEA Global Support Week.

    • Claude
    • Skills
    • MCP
    Internal

    The problem

    The first reply to a new case has to acknowledge the problem, ask for the right information and start the right troubleshooting. The level of detail, the order of questions and the path taken all varied from engineer to engineer.

    What I did

    • Developed specialised Claude skills: packaged instructions Claude loads when a task calls for them. Each covered one part of the workflow: setting the level of detail, structuring the first customer reply, or choosing a troubleshooting path.
    • Connected them to Tanium through MCP connectors, so they work from real product information rather than the model's memory.
    • Encoded support practice from shadowing and triage: which questions to ask first, which details matter for which module, when to escalate.
    • Split the work, integrated the parts and built the demo with interns in Reading and Krakow, then presented it at EMEA Global Support Week to senior support staff and management.

    What it taught me

    Skill design is a design discipline: the structure of the instructions matters as much as the wording. And a tool for engineers has to fit how they really work, which is why doing the job first made the design better.

    This was an internal tool, so there are no screenshots, prompts or internal names here. I'm happy to walk through the architecture and my part in an interview.

  • No. 042024Teesside University hackathon

    Penguin species classifier

    A random forest that tells Adélie, Chinstrap and Gentoo penguins apart from body measurements, built in a day with two other students.

    • Python
    • pandas
    • scikit-learn
    Team of 3

    Context

    A hackathon run by Teesside University to teach A level students machine learning, using the Palmer Penguins dataset: measurements of real penguins from three islands in Antarctica.

    The pipeline

    • Cleaned the data with pandas, and dropped island so the model learns from the animal's body, not where it was found.
    • Split 70/30 with a fixed seed so results repeat.
    • Preprocessed with a ColumnTransformer: mean-fill and scale the numbers, fill and one-hot encode sex.
    • Trained a 100-tree RandomForestClassifier inside one pipeline, so the same preprocessing runs at training and prediction time and test data never leaks into training.
    • Evaluated with a per-species classification report rather than one accuracy number, and plotted a correlation heatmap and pairplot.

    Resource manager · A level project

    • Designed a MySQL database for resources, stock levels and usage over time, served to several client machines from one server.
